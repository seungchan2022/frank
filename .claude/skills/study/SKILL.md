# MVP 학습 스킬 (/study)

> `/study MVP1`, `/study MVP11` 또는 `/study` (인자 없으면 활성 MVP)

## 목적

이미 구현된 MVP를 **흐름 + 개념** 쌍으로 학습한다.
코드 암기가 아니라 "왜 이 기술을 선택했고, 어떻게 동작하는가"를 면접/실무에서 자기 언어로 설명할 수 있게 체화한다.

## 대상 독자

AI 접목 iOS 개발자 취준생. 면접에서 "이 프로젝트에서 JWT 어떻게 쓰셨어요?" 같은 질문에 **흐름 + 개념 + 다른 대안과의 비교**까지 말할 수 있는 수준이 목표.

---

## 전체 흐름 한눈에 보기

```
최초 1회:
  /study MVP{N} 호출
  → 기획 문서 + 코드 읽기
  → 단계 분할 + 각 단계 핵심 개념 추출
  → 로드맵 생성 (history/study/mvp{N}_study_roadmap.md)

단계 사이클 반복 (1단계 → 2단계 → ...):
  ① 전체 흐름도 생성 (웹/iOS 등 모든 플랫폼)
  ② 구간별 개념 설명
     → 설명 과정에서 세부 개념 목록 확정 + 로드맵 갱신
  ③ 어드바이저 팩트체크
  ④ 퀴즈
  ⑤ concepts.md 저장

MVP 전체 완료 후 (1회):
  플래시카드 요약 + mvp{N}_concepts.html + INDEX 갱신
```

## [0] 호출 처리

### 인자 파싱

- `/study MVP{N}` → 해당 MVP 학습 시작
- `/study` (인자 없음) → `progress/active_mvp.txt` 읽어 활성 MVP 확인 후 안내:
  ```
  현재 활성 MVP는 MVP{N}이에요. 이것으로 진행할까요? (y/n)

  만약 다른 MVP를 학습하고 싶다면 `/study MVP{X}` 형식으로 다시 호출하세요.
  ```

### 기존 학습 기록 확인

`history/study/mvp{N}_concepts.md` 존재 시:

```
MVP{N} 학습 기록이 이미 있어요 (마지막 갱신: {날짜}).
어떻게 진행할까요?

A) 처음부터 다시 학습 (기존 파일은 덮어쓰기 전 백업)
B) 이어서 학습 (중단된 단계부터 재개)
C) 기존 내용 업데이트/보완 (특정 단계만 다시 다루기)

→ 답:
```

## [0-B] 학습 로드맵 생성/확인 (최초 1회)

### 신규 학습 시 (로드맵 파일 없을 때)

기획 문서 + 코드를 읽고 `history/study/mvp{N}_study_roadmap.md` 생성:

```markdown
# MVP{N} 학습 로드맵

> 생성: {날짜}

## 전체 학습 흐름

| # | 단계 | 핵심 개념 | 상태 | 상세 파일 |
|---|------|-----------|------|-----------|
| 1 | {단계명} | {개념 목록} | 🔲 미시작 | — |
| 2 | ... | ... | 🔲 미시작 | — |

## 현재 위치

**1단계 {단계명}** 미시작

## 세션 재개 방법
1. 이 파일로 현재 위치 파악
2. 해당 단계 상세 파일 로드
3. 중단된 단계부터 사이클 재개
```

사용자에게 로드맵 확인 요청:
```
📍 MVP{N} 학습 로드맵을 만들었어.

{단계 목록 표 출력}

1단계부터 시작할까요?
```

### 기존 학습 재개 시 (로드맵 파일 있을 때)

로드맵 파일을 읽어 현재 위치를 파악하고 안내:
```
📍 MVP{N} 학습 로드맵 확인

현재 위치: {N}단계 — {단계명} ({상태})

이어서 진행할까요?
```

## [1] 데이터 수집 (최초 로드맵 생성 시)

**추측 금지. 반드시 문서와 코드를 읽은 뒤 추출.**

### 1-A. 기획 문서 로드

```bash
ls history/mvp{N}/       # 완료된 MVP
ls progress/mvp{N}/      # 진행 중인 MVP
```

- `*_기획.md`, `*_roadmap.md`, `M{X}_*.md` 모두 Read
- 사용자 행동 기준으로 단계 분할 (기술 레이어 기준 아님)
- 각 단계에서 처음 등장하는 핵심 개념만 추출

### 1-B. 실제 코드 위치 매핑 (내부 참조용)

- `server/` / `web/` / `ios/` 관련 파일 목록화
- 설명에 코드 스니펫 붙이지 않음. "이 흐름이 코드에 존재하는지" 확인용으로만 사용.

### 1-C. 문서 vs 코드 불일치 검사

문서 주장과 코드가 다르면 **즉시 멈추고 안내**:

```
⚠️ 문서 vs 코드 불일치 발견

- 문서 위치: history/mvp{N}/{파일}.md Line {N}
- 문서 주장: "..."
- 코드 실제: "..."

어떻게 처리할까요?
A) 코드 기준으로 설명
B) 문서 기준으로 설명
C) 둘 다 설명 (변경 이력으로 다루기)
```

## [3] 단계 사이클 (단계마다 반복)

각 단계는 아래 순서로 진행. **서브스텝 하나가 끝날 때마다 사용자 확인 필수.**

---

### 3-0. 흐름도 (단계 시작 시 첫 출력)

단계의 모든 플랫폼(웹/iOS 등) 흐름도를 생성한다. **해설은 이 단계에서 출력하지 않는다.**

**렌더링 규칙 — 흐름 구조에 따라 선택:**

| 흐름 구조 | 방식 | 이유 |
|---|---|---|
| 선형 요청-응답 (순서가 핵심) | Mermaid `sequenceDiagram` → SVG → `<img>` | 시간 축이 명확하게 표현됨 |
| 분기·병렬·폴백 (구조가 핵심) | HTML/CSS 레이아웃 기반 다이어그램 | sequenceDiagram은 모든 것을 순차로 보여서 구조 왜곡 |

**Mermaid SVG 방식 (선형 흐름):**
- inline SVG 임베드 절대 금지 (marker ID 충돌로 화살표 깨짐)
- `.mmd` 파일로 저장 후 `mmdc` CLI로 SVG 변환
- HTML에서 `<img src="flow_xxx.svg">` 방식으로 참조

```bash
npx @mermaid-js/mermaid-cli -i /tmp/flow_xxx.mmd -o /tmp/flow_xxx.svg
```

**HTML/CSS 레이아웃 방식 (분기·병렬 구조):**
- Claude Sunset 테마 적용 (`background: #FDF6F0`, `accent: #D97706`, `heading: #92400E`)
- 분기(HIT/MISS)는 화살표 방향으로, 병렬(join_all)은 박스를 나란히 배치
- 폴백 체인은 `branch-box` 안에 열(column)로 배치
- 레퍼런스: `history/study/flow_feed.html` (MVP1 3단계)

흐름도 생성 후:
```
흐름도를 한 번 훑어봐. ①부터 끝까지 모르는 단어는 그냥 넘겨도 돼.
전체 모양이 어떻게 느껴지는지만 파악하는 거야.
다 보면 말해줘.
```

**참여자(박스) 추상화 수준:**
- 박스 수: 플랫폼당 4~6개 이내 (세부 내부 구조는 branch-box 안에서 추가 가능)
- 파일/클래스 단위로 쪼개지 않음
- 내부 구현 상세는 개념 설명(3-1)에서 다룸

---

### 3-1. 구간별 개념 설명

**흐름상 자연스러운 구간(3~5개 화살표)으로 묶어서** 설명한다.

**진행 순서:**
```
① 구간 범위 안내 (예: "① ~ ⑤ 로그인하고 토큰 저장까지")
② 구간 내 흐름 순서대로 설명 (산문 형식, 예상 질문 선제 답변 포함)
③ "이해됐어? 질문 있어?" 확인
④ 로드맵 세부 개념 상태 갱신
⑤ 다음 구간으로 이동
```

**절대 금지:**
- 화살표 하나씩 한 응답에 출력
- 구간 구분 없이 전체를 한 번에 설명

**노트 작성 형식 (절대 준수):**

```markdown
**② 단계 제목**

산문 2~4문장.

> 💡 **개념 이름이란?**
> 산문으로 정의. "~야." 체로 씀.
> 후속 질문 예상 답변도 같은 블록쿼트 안에 이어서 씀.
```

**절대 금지:** 불릿포인트 목록, 표로 개념 나열, `**무엇인지** / **왜 쓰는지**` 섹션 분할

**선제 답변 원칙:** "이게 뭐야?", "왜 이렇게 해?", "이전 흐름이랑 뭐가 달라?" 같은 예상 질문을 💡 블록쿼트 안에 미리 답변. 설명 후 후속 질문이 계속 나오면 잘못 쓴 것.

---

### 3-2. 어드바이저 팩트체크

모든 구간 설명이 끝나면 **퀴즈 전에** advisor를 호출해서 전체 내용의 기술적 정확성을 검토한다.

```
advisor 호출 목적:
- 개념 설명의 기술적 오류
- 실제 코드와 설명의 불일치
- 누락된 중요 개념
- 오해를 유발하는 표현
```

오류 발견 시 사용자에게 수정 사항을 안내하고 노트/HTML 반영 후 퀴즈로 진행.

---

### 3-3. 자가 확인 퀴즈 (단계 전체 대상)

어드바이저 팩트체크 완료 후 퀴즈를 **한 문제씩** 출제한다.

**절대 금지: 한 응답에 2개 이상의 문제 출력.**

**문제 구성:**
- 선택지 4개 (A/B/C/D)
- 오답지도 흔한 오해/착각을 반영해서 그럴듯하게
- 단계에서 다룬 개념 수에 비례해서 출제:
  - 개념 5개 이하 → 3문제
  - 개념 6~10개 → 5~6문제
  - 개념 10개 초과 → 7~8문제

출제 형식:
```
💡 자가 확인 ({현재}/{전체})

Q. {질문}

  A) ...
  B) ...
  C) ...
  D) ...

→ 답:
```

사용자 답변 후:
```
정답: {X}

- A {✅/❌}: ...
- B {✅/❌}: ...
- C {✅/❌}: ...
- D {✅/❌}: ...
```

### 3-4. concepts.md 저장

퀴즈 완료 후 `history/study/mvp{N}_concepts.md`에 해당 단계 내용을 **즉시 append**.

저장 포맷:

```markdown
## {N}단계: {단계명}

> 학습 일시: {YYYY-MM-DD}
> 상태: ✅ 완료

### 핵심 개념 요약
- {개념1} — 한 줄 요약
- {개념2} — 한 줄 요약

### 흐름 + 개념 상세
{구간별 설명 내용}

### 자가 확인 기록
Q: {질문}
사용자 답: {답변}
정답: {정답} / 포인트: {보완 내용}
```

저장 완료 후 로드맵 상태 갱신:
- 해당 단계 `🔄 진행 중` → `✅ 완료`
- 현재 위치를 다음 단계로 갱신

## [4] MVP 전체 완료 처리 (모든 단계 완료 후 1회)

모든 단계 사이클이 끝난 뒤:

### 4-A. 플래시카드 요약

`mvp{N}_concepts.md` 파일 맨 위에 복습용 요약 삽입:

```markdown
# MVP{N} 학습 기록

> 학습 완료: {날짜}
> 커버한 단계: {N}개

## 🎴 핵심 요약 (복습용)

| # | 질문 | 핵심 답변 |
|---|------|----------|
| 1 | JWT를 왜 썼나? | 서버 세션 저장 불필요, 수평 확장 용이 |
| 2 | httpOnly 쿠키? | JS 접근 차단 → XSS 방어 |
| ... | ... | ... |
```

### 4-B. HTML 생성

`history/study/mvp{N}_concepts.html` 생성.

**Claude Sunset 테마:**
```css
--bg: #FDF6F0; --text: #2D2926; --accent: #D97706;
--accent-light: #FEF3C7; --heading: #92400E;
--border: #E5D5C5; --code-bg: #FFF7ED; --card-bg: #FFFFFF;
```

- 모바일 최적화 (max-width: 480px)
- 플래시카드는 접기/펼치기 가능하게 (details/summary)

### 4-C. INDEX 갱신

`history/INDEX.md`에 학습 기록 항목 추가.

## 절대 금지

- **추측 설명 금지** — 기획 문서 + 코드 읽기 전에 설명 시작 금지
- **코드 스니펫 붙여넣기 금지** — 내부 확인용으로만 코드 읽기
- **한 번에 여러 구간 동시 설명 금지**
- **자가 확인 생략 금지** — 단계마다 필수
- **어드바이저 팩트체크 생략 금지** — 퀴즈 전에 반드시 호출

# ST-1: A3 태그-기사 매칭 전략 진단

> 유형: research | 의존: 없음 | 예상: 1h

## 목적

A3 매칭 불일치 원인을 진단하고 구현 전략(통합 캐시 vs 사후 분류)을 결정한다.

## 배경

현재 `get_feed`는 태그별로 독립 검색 쿼리를 날린다 (`join_all`). 같은 기사가 두 태그 검색에 등장해도 각각 독립 `FeedItem`으로 처리되어 `tag_id` 귀속이 다르게 붙는다. "오픈소스" 탭에 의약품 기사가 뜨는 것은 검색 쿼리 자체가 느슨한 것이 원인.

## 진단 질문 (A3 확정 반영: 사후 분류 제거)

1. 검색 쿼리를 정밀화(ST-2, ST-3)하면 무관 기사 혼입이 충분히 차단되는가?
2. 통합 캐시(태그별 캐시 공유) 구현이 필요한가 — 동일 user_id + 단기 TTL 내 동일 쿼리 캐시 히트로 일관성 확보 여부

> 사후 분류(LLM/규칙 기반 태그 귀속) 전략은 A3 운영 정의에서 기각. 이 진단에서 고려하지 않음.

## 진단 방법

```bash
# 서버 로그에서 실제 검색 쿼리 확인
scripts/deploy.sh --target=api --native
# 앱에서 피드 호출 → 로그에서 "feed search query" 라인 확인
grep "feed search query" <log>
```

## 결정 기준

| 전략 | 선택 조건 |
|------|-----------|
| 쿼리 정밀화만으로 충분 (케이스 A) | ST-2/ST-3 적용 시 무관 기사 0건 달성 가능 → ST-6 스킵 |
| 통합 캐시 추가 (케이스 B) | 쿼리는 정밀하지만 캐시 TTL 안에서 tag_id 귀속 불일치 재현 시 |

> 케이스 C(사후 분류)는 기각. 재현 시 step-1로 재진입하지 않음.

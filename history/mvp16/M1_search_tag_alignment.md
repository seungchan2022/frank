# M1: 피드 검색·태그 정합

> 프로젝트: Frank MVP16
> 상태: 대기
> 예상 기간: 3~5일
> 의존성: 없음 (서버 우선)

## 목표

올바른 기사가 올바른 태그로 들어오도록 피드 검색 파이프라인의 정합성을 회복한다. 무관 토픽 혼입 차단 + 한국어 기사 노출 + 태그별/전체 매칭 일관성 확보.

## 배경 (`_review_notes.md` §2 서버: 검색·태그 정합)

실사용 피드백에서 다음 3건이 발견되었다 — A1(무관 토픽 혼입), A2(한국어 기사 0건), A3(태그 필터 매칭 불일치).

## 포함 항목

### A1. "모바일 개발" 탭에 무관한 기사 (DEBT-MVP16-01)

- **상황**: 사용자가 피드의 "모바일 개발" 태그 탭을 클릭
- **현재**: Tavily 검색 결과에 포켓몬 카드/게임 기사 등 무관 토픽 혼입. 정상 기사도 일부 포함되긴 함 (예: `Vibe coding platform Lovable now available for iPhone`).
- **기대**: 태그와 정합한 기사만 노출
- **수정 결**: `server/src/api/feed.rs::tag_search_keyword()` 키워드 매핑 정밀화. Tavily 호출에 언어/도메인 필터 추가. 또는 후처리 LLM 보정 옵션 검토.

### A2. 한국어 기사 0건

- **상황**: 어떤 태그를 검색해도 결과에 한국어 기사가 거의 없음
- **현재**: Tavily 쿼리가 영어 일변. KR 도메인/언어 옵션 미적용.
- **기대**: 한국어 기사도 일정 비율 포함
- **수정 결**: Tavily 호출에 한국어 키워드 병행 + KR 도메인/언어 옵션 추가. 또는 KR/EN 두 패스로 분할 후 합치기.

### A3. 태그 필터 합산·매칭 정합

- **상황**: 전체 피드 N개 기사를 각 태그 필터로 나눠 합치면 N과 안 맞음. "오픈소스" 태그 필터에 IBS 의약품 같은 무관 기사 포함 사례 발견.
- **현재**: 전체 피드 검색과 태그별 검색이 별도 쿼리. 한 기사가 다른 태그 검색 시 매칭 결과가 일관되지 않음. (한 기사가 여러 태그에 속할 수 있어 합산 ≠ 전체는 정상 — 진짜 문제는 **매칭 자체가 잘못된 것**)
- **기대**: 매칭은 정확. 한 기사가 N개 태그에 속하면 그 매칭이 일관됨.
- **수정 결**: 검색 전략 재설계 — (a) 태그별 검색 후 통합·캐시, (b) 전체 검색 + 사후 태그 분류. step-6 진단 후 결정.

## 미결정 (워크플로우에서 결정)

| 항목 | 결정 시점 | 비고 |
|------|-----------|------|
| **A3 운영 정의** — "매칭 일관성"의 의미 결정. 후보: (i) 같은 검색 두 번 = 같은 결과(통계적 안정), (ii) 한 기사가 N개 태그에 속하면 모든 N태그 검색에 등장(carry) | step-1 | (ii)는 데이터 모델 변경 필요 — 현재 `FeedItem.tag_id: Option<Uuid>` 단일 필드로는 한 기사 N태그 carry 불가. (ii) 선택 시 `tags: Vec<Uuid>`로 모델 변경 + MVP15 데이터 마이그레이션. (i) 선택 시 모델 변경 없음 |
| A3 매칭 전략 구현 (통합 캐시 vs 사후 분류) | step-6 진단 후 | 운영 정의 결정 후 |

## 성공 기준 (Definition of Done)

- [ ] `tag_search_keyword()` 매핑 정밀화 또는 검색 호출 파이프라인 보정 적용
- [ ] Tavily 호출에 언어/도메인 필터 또는 KR/EN 멀티패스 적용
- [ ] 태그-기사 매칭 전략 결정 + 구현 + 단위 테스트
- [ ] 본인 직접 사용: "모바일 개발" 탭에서 무관 토픽 0건 확인 (E2E)
- [ ] 본인 직접 사용: 임의 태그 탭에서 한국어 기사 1건 이상 노출 확인 (E2E)
- [ ] 본인 직접 사용: 같은 기사가 두 태그 검색에 등장 시 매칭 일관성 확인 (E2E)
- [ ] 서버 단위·통합 테스트 통과 (`cargo test`)
- [ ] 비용 영향 검토: 호출 수 증가가 무료 한도 위반으로 이어지지 않음 확인 (`progress/mvp16/cost_log.md` 신규 또는 기존 갱신)
